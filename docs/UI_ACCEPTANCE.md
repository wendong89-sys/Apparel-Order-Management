# UI 专业软件级验收标准

本项目的 UI 目标是“生产管理软件”，不是营销页。界面需要安静、清晰、高密度、可反复操作，业务人员能快速看状态、找订单、推进流程。

## 1. 验收门槛

UI 满分 10 分，低于 9 分不得通过。每次提交前运行：

```bash
npm run ui:score
```

总验收运行：

```bash
npm run check
```

## 2. 评分项

| 评分项 | 分值 | 验收标准 |
| --- | ---: | --- |
| 信息架构 | 1.5 | 左侧导航、顶部操作、页面标题、业务摘要层级清楚 |
| 生产工作流首屏 | 1.2 | 看板首屏能看到订单量、评分、待处理状态和最近订单 |
| 视觉系统 | 1.3 | 使用统一色板、间距、圆角、阴影、边框，不是临时拼接 |
| 表格与数据密度 | 1.2 | 表格适合扫描，列宽稳定，状态/评分/工厂信息清楚 |
| 状态语义 | 1.0 | 成功、警告、风险、禁用状态颜色明确且不只依赖颜色 |
| 表单可用性 | 1.0 | 标签、输入、分区、提示、按钮排布清楚，移动端不溢出 |
| 响应式 | 1.0 | 桌面、平板、手机都能操作，导航和表格不重叠 |
| 可访问性 | 0.8 | 有 focus-visible、足够对比度、禁用态、减少动效支持 |
| 工程一致性 | 1.0 | UI 标准写入文档和脚本，质量门自动检查 |

## 3. 必须满足的硬规则

1. 禁止新增营销式大 hero。
2. 禁止卡片套卡片作为页面主要结构。
3. 禁止文字溢出按钮或表格单元格。
4. 禁止只有颜色没有文字的状态表达。
5. 禁止低于 9 分 UI 评分合并。
6. 页面必须保留订单、评分、分厂、生产、质检这些主流程。

## 4. 当前 UI 发布标准

当前版本必须至少满足：

- `npm run ui:score` 达到 9 分以上。
- `npm run check` 全部通过。
- 桌面端看板无控制台错误。
- 移动端首屏导航、顶部按钮和订单表格不重叠。
