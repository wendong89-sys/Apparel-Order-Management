# 开发流程

## 1. 目标

本项目按“先跑通业务闭环，再升级技术架构”的方式开发。任何版本都必须能完成客户订单从录入到分厂、生产、质检、出货的主流程。

## 2. 开发阶段

| 阶段 | 目标 | 交付物 |
| --- | --- | --- |
| 需求 LOOP | 固化业务流程、角色、状态、评分规则 | `LOOP.md` |
| MVP | 做出可直接使用的 Web 版本 | `index.html`、`src/` |
| 轻量后端 | 从 localStorage 扩展到服务端 JSON 持久化 | `server/`、`data/` |
| 数据库持久化 | 从 JSON 文件升级到数据库 | API、数据库迁移 |
| 多人协作 | 登录、权限、消息通知 | 用户与权限模块 |
| 生产部署 | Docker、CI、备份、监控 | 部署文档 |

## 3. 每次开发的标准流程

1. 明确本次改动对应哪个业务节点。
2. 更新或确认 LOOP 中的业务规则。
3. 修改数据结构。
4. 修改页面和交互。
5. 增加必要校验。
6. 跑通主流程。
7. 更新 README 或 docs。
8. 做一次 10 分验收评分。
9. 运行 `npm run check`。

## 4. 发布标准

正式版本必须达到 9 分以上：

- 主流程可跑通
- 低于 9 分订单不能下发
- 关键操作有日志
- 文档能让新开发者本地运行
- 页面能让业务人员独立操作

如果验收分数低于 9 分，必须补齐短板后再发布。

## 5. 自动化验收

每次提交前运行：

```bash
npm run check
```

它会依次执行：

- `npm run test`：验证评分、分厂、质检出货等领域规则
- 服务端测试：验证登录、鉴权、API 状态门和服务端禁止违规分厂/出货
- `npm run build`：验证前端可打包
- `npm audit --audit-level=moderate`：验证依赖没有中高风险告警
- `npm run score`：执行项目 9 分验收
- `npm run ui:score`：执行 UI 专业软件级验收

任何一步失败，都不能作为正式版本发布。

## 6. 分支建议

- `main`：稳定版本
- `dev`：开发版本
- `feature/order-score`：具体功能分支
- `fix/factory-assignment`：缺陷修复分支

## 7. 代码规范

- 页面文案使用中文，字段命名使用英文。
- 核心状态和评分规则集中维护。
- 不在页面中硬编码业务分数。
- 每个关键动作都写入操作日志。
- 不允许绕过 9 分下发规则。
- 业务规则优先写在 `src/domain.js`，不要散落在页面点击事件里。
- 新增核心规则必须补充 `tests/domain.test.js`。
- 新增 API 必须补充 `tests/server.test.js`。
