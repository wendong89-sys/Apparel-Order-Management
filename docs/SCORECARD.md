# 9 分评分体系

## 1. 订单评分

订单评分满分 10 分，系统按资料完整度、生产可执行性和交付风险自动计算。

| 评分项 | 分值 | 系统判断 |
| --- | ---: | --- |
| 客户与交期信息 | 1.0 | 客户、联系人、电话、下单日期、计划交期完整 |
| 尺码数量 | 1.5 | 至少一行产品，合计数量大于 0 |
| 面料信息 | 1.2 | 主色、拼色/里布/填充物、面料备注基本清楚 |
| 辅料信息 | 1.0 | 拉链、扣子、反光条、缝纫线、商标、吊牌中关键项明确 |
| 定制内容 | 1.0 | 定制类型、内容、位置、logo 或效果图明确 |
| 技术参数 | 1.2 | 技术确认完成，有技术说明 |
| 采购确认 | 1.0 | 采购确认完成，有到料或库存说明 |
| 工厂匹配 | 1.0 | 选择的工厂能承接该品类和工艺 |
| 质量与交付风险 | 1.1 | 没有未处理异常，交付风险可控 |

## 2. 下发规则

- 分数低于 6：不能提交审核。
- 分数低于 9：不能分配工厂。
- 分数达到 9：可以分配 1 号工厂或 2 号工厂。
- 已分厂订单如果新增异常，系统应重新显示风险。

## 3. 重做机制

当订单低于 9 分：

1. 系统展示扣分项。
2. 订单进入“待资料完善”。
3. 对应角色补充资料。
4. 系统重新计算分数。
5. 达到 9 分后继续审核和分厂。

## 4. 项目评分

项目发布也采用 10 分制。低于 9 分的版本不应作为正式版本发布。

| 项目项 | 分值 |
| --- | ---: |
| 业务闭环完整度 | 2.0 |
| 数据结构清晰度 | 1.5 |
| 页面可用性 | 1.5 |
| 状态与规则控制 | 1.5 |
| 开源文档 | 1.0 |
| 本地运行门槛 | 1.0 |
| 扩展性 | 1.0 |
| 视觉与交互质量 | 0.5 |

当前 MVP 自动验收分：运行 `npm run score` 获取。

主要依据：

- 主流程已经可操作。
- 9 分规则已经进入页面逻辑。
- 文档齐全。
- 本地运行门槛低。

仍需提升：

- 后端数据库版本。
- 多用户真实登录。
- 文件上传到对象存储。
- 自动化测试和 CI。

## 5. 自动化验收命令

```bash
npm run test
npm run build
npm run score
npm run check
```

`npm run check` 是发布前总门槛。低于 9 分时，脚本会失败并提示重做短板模块。
